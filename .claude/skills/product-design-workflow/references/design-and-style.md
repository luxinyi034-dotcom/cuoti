## 1. 从参考图提炼风格

使用者给参考图时，先用几句话说出你看到的“意思”，再落成可执行的规则：

- **气质**：比如“安静、纸张感、低饱和、像笔记本”。
- **色板**：一个主色系 + 纸张底色 + 文字色 + 线条色 + 少量状态色（对 / 错 / 提醒）。写成 CSS 变量：
  ```css
  :root {
    --paper: #FBFAF6; --paper-2: #F7F4EE;   /* 底色两层 */
    --ink: #3F4A40; --warm: #6E6A60; --muted: #9A958A;  /* 文字三层 */
    --line: #E4DED3;
    --sage: #8FA28A; --sage-deep: #6E8068; --sage-soft: #E5E9DF;  /* 主色三层 */
    --wrong: #B5614F; --wrong-soft: #F6E7E2;  /* 状态色只用于对错 */
  }
  ```
- **字体**：标题用一款有气质的衬线体，正文用清晰的无衬线体，英文内容用阅读型衬线体。
- **形状**：统一圆角（如 10 / 14 / 20 三档）、1px 细线、很轻的阴影。

**为什么不用多种颜色区分类别**：颜色一多就花，层次反而乱。用同一色系，靠图标 + 名称 + 位置区分（比如左侧菜单里“叠层 = 主题表达，箭头 = 功能表达，铅笔 = 写作笔记”），整体才统一、耐看。

## 2. 设计稿画布

- 一个可以打开浏览的页面（或 Artifact），每张设计稿是一个“板”，有编号和一句话标题，按排分组（第 N 排：某个功能）。
- **大决定给 2–3 个方案并排**：每个方案下面写一句“好处 / 代价”，让使用者挑。比如“三种一起导入：A 一页三栏 / B 标签页 / C 分步”。
- **用真实内容**：真实的英文句子、真实长度的中文、很长的答案、很多条目的列表。好不好看只能在真实内容下判断。
- **画出各种状态**：空的、进行中、完成、出错、内容很长、iPad 竖屏、手机。
- **能点的演示**：交互复杂时（比如学习流程），做一个可以点着走一遍的演示页，比静态图更容易确认。
- **替换不堆积**：方案定了、改过的板直接替换掉旧的，画布保持干净。
- 确认后在 PRD 里引用设计稿编号（“设计稿 CH”），以后改动能追溯。

## 3. 新功能怎么保持同一风格

- 先在已有界面里找最像的组件复用（卡片、行、标签、分段按钮、弹出层），不新造。
- 新的样式也只用变量，不写死颜色。
- 同类信息在不同页面长得一样（比如“今天学这个”卡在首页和今日学习是同一个组件），逻辑也只写一处——两处显示不一致会让使用者觉得“逻辑混乱”。
- 文案语气统一：短句、口语、说清楚“点了会怎样”（“换一个话题”“过几天再说”“再点一次，确认清空”）。
- 会删除或覆盖东西的按钮：点两次确认，并说明后果。

## 4. 美观自查清单（截图后逐条看）

- 对齐：同一列的左边缘对齐；按钮在行内垂直居中。
- 行距和高度：输入框、标签的高度和文字行高协调，不把某一行撑得特别高。
- 留白：不出现一行只有一个元素、旁边大片空白；卡片内外边距一致。
- 长内容：特别长的文字会换行、完整显示，不被截断、不溢出容器。
- 遮挡：固定在底部的操作条、浮动按钮不挡住正在操作的内容（必要时自动滚动）。
- 层次：一屏里只有一个主按钮（实心），其他是描边或文字按钮。
- 颜色：只用色板里的颜色；红色只表示错误/危险。
- 空状态：没有内容时有一张说明卡和下一步按钮（比如“从导入开始”），而不是一片空白或误导的文字（比如没有内容却显示“都学过了”）。
